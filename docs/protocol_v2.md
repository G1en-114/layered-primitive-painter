# 协议 v2：为什么改、怎么定下来的

时间：2026-11-15。这份记录说明 v2 的每个决定背后的实验，以及怎么复现。

## 1. 问题：训练数据的画质上限卡在哪

GPT 会话里的诊断实验（`tools/probe_raw_supervision.py`）先给了信号：8 张人脸上，已有的离散化
训练目标 26.18 dB，只做小幅度连续修正就到 31.48 dB，而修正完再压回码本又掉回 27.42 dB。
说明**离散化本身**损失很大，比拟合算法的问题大。

要回答的问题：损失具体在哪个属性上？换掉它能拿回多少？

## 2. 方法：逐属性量化

`tools/codebook_study.py`：

1. **采集无偏的连续参数**：分解器加了 `quantize=False` 模式，拟合中途不往码本上吸、层间也用连续
   参数叠加。否则采到的参数分布会偏向旧码本，用它拟合新码本是自己证明自己。
   640 张人脸（CelebAMask 第 29 分片），在 DCU 上用原生 HIP 光栅化跑的，1.4 张/秒。
2. **拟合 / 评估分开**：前 512 张拟合候选码本，后 128 张只用来评估。
3. **每次只量化一个属性**，其余保持连续，量出这一项单独的代价。

## 3. 结果（128 张留出人脸，连续上限 32.42 dB）

| 只量化这一项 | v1 | 数据驱动码本 | 说明 |
|---|---:|---:|---|
| 位置 x/y（256 档） | −2.55 | | 512 档 −1.71，1024 档 −1.42 |
| **形状（每个 β 1024 个对数协方差码字）** | **−6.55** | −5.86 | 重新拟合码本几乎没用 |
| 颜色（4096 Oklab 码字） | −1.47 | **−0.38** | 先验码本浪费在人脸用不到的颜色上 |
| 不透明度（16 档） | −0.09 | | 不是问题 |

形状的候选表示（β 不量化）：

| 形状表示 | 损失 | 每图元 token 数 |
|---|---:|---:|
| 码本 1024 | −6.10 | 1 |
| 码本 4096 | −3.60 | 1 |
| 两级残差码本 1024+1024 | −0.31 | 2 |
| **拆开：log σx、log σy、θ 各 128 档** | **−0.19** | 3 |
| 拆开，各 256 档 | −0.05 | 3 |
| β 四档 {1,2,4,8} | −0.39 | — |
| **β 八档（对数均匀）** | **−0.07** | — |

**为什么形状码本这么差**：形状是三维的（σx、σy、θ），而小尺寸、硬边（β 大）的图元对形状误差极其
敏感。1024 个码字铺在三维空间里每一维只有约 10 档，再怎么挑位置也不够。这是**容量**问题，不是
码字摆放问题——这也是为什么数据驱动码本只拿回 0.7 dB。

**为什么选"拆开"而不是残差码本**（两者损失接近）：

1. 有序分档能直接用傅里叶嵌入和高斯软标签，模型学到的是"大一点 / 小一点"的平滑关系；码本编号
   是任意排列的，相邻编号没有关系。
2. 可编辑性：App 里改宽、高、角度就是改对应 token，不需要找最近码字。
3. 代价是每个图元多 3 步属性解码（6 → 9 步）。属性解码器很小，后面用 CUDA Graph / 融合 kernel
   压这部分开销，本来就在部署计划里。

## 4. v2 的最终定义

```
事件 → x(512) → y(512) → log σx(128) → log σy(128) → θ(128, 周期) → β(8, 对数) → 颜色(4096) → α(16)
```

- 形状先规范化：σx ≥ σy，θ ∈ [0, π)。θ 是周期量：量化时 π 附近绕回 0；嵌入用整数频率的傅里叶
  特征，软标签按圆周距离算。
- 颜色码本 `assets/codebooks/color_oklab_v2.npy`：512 张人脸的连续颜色 + 20% 均匀先验颜色做
  k-means。先验部分保证人脸里少见的高饱和色仍可达（后面动漫风格要用）。人脸颜色平均误差 0.0071，
  均匀颜色 0.0119（Oklab 距离）。
- 上下文预算不变：每个图元仍只占主干的一个位置，最坏情况 1001 / 1024。

整套 v2 离散化（研究里先连续后量化）：**24.93 dB（v1）→ 30.23 dB**。
实际分解（量化感知拟合，16 张留出人脸）：**26.21 dB（v1）→ 30.08 dB（v2）**，而且更快
（不用在 1024 个码字里搜最近邻）：同等条件 1.40 → 1.06 秒/张。

## 5. 兼容性

- `protocol.json` 是 v2；`protocols/v1.json` 保留 v1，旧数据（`data/seq/v0`）、GPT 的动漫两层
  试验协议、旧 checkpoint 都按 v1 读。编解码器、模型、采样器都从协议读属性列表，两版共用代码。
- 分解工具的 `config.json` 现在总是记录协议版本和文件哈希；训练前检查数据目录的协议版本，不一致
  直接报错，不会把 v1 数据喂给 v2 模型。

## 6. 复现

```sh
# DCU 或本机：采集连续参数（不量化）
python tools/codebook_study.py collect --data data/celebamask256 --shard 29 --count 640 \
    --out out/codebook_study/faces.npz
# 拟合候选码本 + 逐属性评估
python tools/codebook_study.py evaluate --collected out/codebook_study/faces.npz \
    --images data/celebamask256 --fit-count 512 --out out/codebook_study
```

## 7. 还剩的损失

v2 离连续上限还差约 2.2 dB，最大的一项是位置（512 档 −1.71）。1024 档只多拿 0.29 dB，说明剩下的
主要是极小、硬边图元对亚像素位置的敏感，不值得再加词表。下一步提升更可能来自拟合本身
（全图联合的量化感知微调；GPT 实验里对人脸有约 +1.5 dB）。

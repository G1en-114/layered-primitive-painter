# 协议 v3 设计：人脸、动漫、通用场景共用一套分层协议（2026-11-16）

状态：设计稿，尚未实现。v2 人脸协议、数据与 checkpoint 保持不变，作为对照组。
目标：给最终的 1B 模型提供一套统一协议，同时覆盖真人人脸（CelebAMask-HQ）、动漫人脸
（anime_face_control_60k）和通用场景（COCO Panoptic，以后加 ADE20K）。
背景与约束见 [通用分层绘画设计](general_painter_design.md)、[数据扩充路线](data_expansion_plan.md)。

## 1. 图层 = 槽位 + 语义

v2 中“图层编号”就等于语义：2 号永远是皮肤。通用图片做不到这一点，所以 v3 把两件事拆开。

- **槽位（slot）**：决定绘制顺序和编辑目标，共 K = 8 个。事件为 `LAYER_0..7`、`REDRAW_0..7`、`REFINE_0..7`。
  合成顺序仍然是先按槽位，再按槽位内的先后。
- **语义（sem）**：每条 `LAYER_k` 控制记录额外带一个语义 token，词表约 160 项：
  - 0 号：未知或泛指。
  - 人脸部件：背景、身体衣服、皮肤、五官、头发、配饰。真人和动漫共用这一组。
  - COCO Panoptic 的 133 个类别：80 个物体类，53 个背景类。
  - 少量合并后的背景大类：天空、地面或水面、建筑、植物。
- 模型改动：控制位置在预测事件之后，再由属性解码器预测语义，词表约 160。
  语义作为输入时，和事件 embedding 相加。
- 编辑能力：用户说“把猫重画成橘猫”，先按语义找到槽位，再生成 `REDRAW_k`。
  一张图里有两只猫时，它们占两个槽位，语义相同。

**为什么 K = 8**：人脸已经用掉 6 层；通用场景约等于 3 个背景槽 + 4 个主要物体 + 1 个“其余小物体”槽。
再多的话，每个槽分到的图元太少，控制记录的开销也会变大。

## 2. 各数据源怎么映射到槽位

| 来源 | 槽位分配 |
|---|---|
| CelebAMask-HQ | 沿用 v2 的 6 层和顺序：0 背景、1 身体、2 皮肤、3 五官、4 头发、5 配饰；语义对应人脸部件 |
| 动漫人脸 | 与真人相同的 6 层。角色/背景来自 anime-seg；皮肤和五官由 28 个关键点切出；头发 = 角色 − 皮肤 − 身体（按位置启发式）。属于伪标签，单独记录来源和置信度 |
| COCO Panoptic | 背景类按大类合并成 ≤ 3 个槽，顺序为天空 → 地面/水面 → 其他背景。面积 ≥ 1.5% 的物体实例取最大的 4 个，每个占一个槽，按包围框下沿从远到近排序（下沿越靠下越近，越晚画）。其余小物体合并成一个“其余物体”槽，画在背景之后、主要物体之前 |

裁剪：短边缩放到 256，再裁成正方形，裁剪框尽量盖住最大的物体。
如果裁掉了最大物体 40% 以上的面积，丢弃这张图。

遮挡说明：全景分割只给出“可见像素归谁”，没有真实的遮挡顺序和被挡住的内容。
“按下沿排序”只是近似，所以只承诺“可见区域编辑”，不承诺“移走物体后补出背景”。

## 3. 图元预算与上下文

- v2 人脸每张图的预算是 96 + 128 + 192 + 224 + 256 + 64 = 960，平均实际用到约 729。
- v3 改成**按图分配**：每张图的总预算 B 按槽分配，权重为 √面积 × 边缘密度，每个槽至少 16 个。
  人脸保持 v2 的分配方式。
- 上下文：v2 是 1024 个位置。通用场景是否需要 1536 个图元、对应 2048 的上下文，要靠试验批来定：
  在 500 张试验图上比较 B = 512、768、1024、1536 时的 PSNR、边缘误差和序列长度。
  1024 → 1536 如果提升不到 0.5 dB，就保持 1024，省下注意力开销和推理延迟。

## 4. 码本

- 形状是分开分档的均匀 bin，不依赖数据，所以保持不变：x/y 各 512 档，σ 128 档，θ 128 档，β 8 档，alpha 16 档。
- **颜色码本要重新拟合**：v2 是在人脸上做的 k-means，加 20% 均匀先验色。COCO 的绿色和蓝色很多，动漫的饱和色也很多。
  v3 在三个来源各取一部分，用连续分解结果重新拟合，仍是 4096 个颜色加 20% 均匀先验。
- 码本一变，旧 token 的含义就跟着变，所以 1B 用的全部数据（人脸也包括在内）都要按 v3 重新分解。
  按两台机器每天约 50 万张来算，人脸 4 条轨迹约 6 小时。v2 数据与模型保留作对照。

## 5. 文字描述

- 人脸：沿用现有中文 VLM 描述和属性模板。
- 动漫：上游标签转成中文模板，加“动漫风格”之类的风格词。
- COCO：类别模板，例如“草地上有一只猫和一只狗，背景是天空”，由全景分割的类别、数量和大致位置生成。
  再用 Qwen2.5-VL 在 DCU 上补写一部分中文描述。这个任务很长，正好在远程 GPU 空闲时填充算力。
- 风格和来源只写在文字里（照片 / 动漫），不进协议，以便以后做风格迁移。

## 6. 条件：文字、图片或两者都有

为了做图生图，v3 模型增加一个图像条件分支：冻结的 Chinese-CLIP 视觉塔输出 patch token，
主干通过交叉注意力读取，和画布反馈是同一个机制。训练时随机组合条件：
只有文字 / 只有图片 / 文字加图片 / 都没有，各条件分别做 dropout，CFG 依然可用。
图片条件的训练配对就是分解时用的原图，不需要额外标注。
推理时可以做：临摹成图元、局部重画（REDRAW + 文字）、风格迁移（动漫后训练之后）。

## 7. 验证顺序

1. **试验批**：从 COCO val2017（5000 张，已下载）中选 1500 张，动物、物体、风景各 500 张。
   做槽位映射 → 裁剪 → 按 v2 码本分解。检查 PSNR、各槽质量、预算曲线和耗时。
2. 用三个来源的连续分解结果拟合 v3 颜色码本，在独立样本上和 v2 码本比较量化损失。
3. 动漫六层伪标签：抽查 200 张，记录失败类型。
4. 模型改动：语义头、8 个槽、图像条件分支，同时补测试。
   用 small 在混合小数据上跑通，再按规模放大到 base 和 1B。

每一步都单独记录数据版本、码本哈希和协议哈希，不和 v2 的产物混放。

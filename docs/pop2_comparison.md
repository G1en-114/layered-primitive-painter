## 已核对的公开实现

- [中文说明](https://github.com/wonderfulearth/primitive-operation-painter/blob/main/README.zh-CN.md)

- [架构说明](https://github.com/wonderfulearth/primitive-operation-painter/blob/main/docs/architecture.md)

POP 2 把九个属性合并为一个完整图元的历史位置，当前图元内部仍逐属性生成。
绘画按全局、粗区域和细区域组织，应用可按区域选择保留历史；其注意力窗口仍是 1024。
工具可以为同一图片生成不同的随机轨迹，并在扰动流程中暂停和重新访问区域。

其公开模型约 1B 参数、512px 有效画布，主要围绕动漫人脸训练。
我们的当前试训约 22M、256px，主要数据是人脸照片；不能把两者的效果差仅归因于某一结构。
“600万条序列”也不能直接解释成“600万张独立图片”，应分别统计图片数、轨迹版本数和描述版本数。

## 对本项目的采用建议

| 思路 | 采用方式 | 优先级与验证 |
|---|---|---|
| 同图多轨迹 | 先给同一高质量原图制作 2–4 个分解版本，保留稳定图元顺序规则 | 高；与单轨迹基线比较，所有版本严格处于同一 split |
| 全局到局部 | 在每个语义/实例层内部加空间粗绘和局部细化 | 高；比较细线、眼睛和轮廓，不能把网格当成语义层 |
| 区域相关历史 | 保留全局布局、当前对象和邻域图元，再开始短段续画 | 中；测一致性和推理成本，承认遗忘的远处历史可能产生影响 |
| 编辑前缀与分支 | 保存编辑状态与前缀，支持同一位置多次续画比较 | 高；把现有 REDRAW/REFINE 协议接成真实推理流程 |
| 熵自适应采样 | 与当前 top-p 在固定模型和随机种子上做对照 | 中；评价坏图比例、文本遵循和多样性，不预设必胜 |
| 共享历史属性监督 | 保留其“历史压缩、图元内依赖”的目标 | 已有相近目标；当前两级结构优先保持，是否换注意力实现另测 |

先完善数据与局部任务，再考虑更大模型。不要立即复制 1B、多分支 FlexAttention 和完整原生编辑器，
因为这会同时改变性能条件、训练复杂度和部署工作量。

## 与刚完成的数据工作的关系

动漫首批 1000 张已经关联原图、头像、文字模板和两层伪标签；953 张通过自动检查。
8 张离散图元试验平均重建约 21.78 dB，说明当前教师仍要改善，不能用重复轨迹数量掩盖质量不足。
其中 4 张连续有界修正达到约 27.37 dB，只是有原图的逐图实验。

采用顺序：改善教师及编码 → 同图少量多轨迹 → 区域修复任务 → 固定基线的采样对照 →
通用实例图层与更大规模数据。多轨迹与更多独立原图是互补工作，不能互相替代。

## 用户确认仓库后进一步核对的源码

- `model/region_constraints.py`：对区域内可选的中心坐标 token 建立合法集合，训练和推理的区域约束
  需要与数据生成器保持一致；限制中心不等于完整图元不会越过区域边界。
- `app/src/redraw_context.rs`：重绘先生成新的合法前缀并保留图元 ID 映射，某些后续阶段历史需要排队，
  不能任意把粗阶段 marker 插到细阶段之后。可迁移的是“编辑后重建合法上下文”的原则。
- `app/src/inference/context_window.rs`：仅在容量不足时重规划窗口；缓存按完全相同且顺序相同的前缀复用，
  原始完整历史保留在外部。区域变化不会自动成为随意重排历史的理由。
- `app/src/inference/sampling.rs`：用 Rényi 有效支持集确定候选数，再均匀抽取入选排名；源码还检查
  优化前后随机流一致性。移植采样时除了比较图像，也要比较 token 与 RNG 消耗。
- `data_tools/image_to_sequence/src/shader.wgsl`：候选几何确定后积累颜色求解所需的统计量，并计算误差变化。
  值得实验“几何优化与颜色拟合交替”，但有序广义高斯、可变 alpha 和量化码本与其设定不同，不能照搬公式。

另须注意根目录保留了 POP 1 文件；本次 POP 2 模型核对以 `model/` 为准。

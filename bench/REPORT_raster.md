# 光栅化算子优化报告：Triton tile 光栅化器（前向 + 反向）

## 问题

分层分解器每一步都要把一层图元（B 张图 × N 个广义 2D 高斯，按顺序 over 合成）渲染成预乘颜色
P [B,3,H,W] 和透射率 T [B,1,H,W]，再对 xy、conic（→ σ、θ）、β、rgb、α 反向求梯度。

- 真实形状：分解器 B=8–16，N≤256（一层），256×256，前向 + 反向；整图渲染 N≈1000，只做前向。
- 基线：`render/reference.py` 稠密实现，每个图元对每个像素都计算（B·N·H·W），autograd 保存全部中间量。
- 上限分析：输出只有几 MB，访存可以忽略，耗时取决于实际计算的"像素 × 图元"组合数。tile 版只计算
  包围盒和 tile 有重叠的组合：分解器场景下是稠密版的 14%，经过 v3 剔除后约 10%。

## 设计

1. torch 打包：每个图元 12 个 float（x, y, A, B, C, β, α, rgb, g(c²), ∂g(c²)/∂β）连续存放。
2. torch 分箱：16×16 tile；稳定压缩保证每个 tile 的列表保持绘制顺序；α=0 的 padding 图元直接跳过，结果完全一致。
3. 前向 kernel：每个 (图, tile) 一个 program，256 个像素放在寄存器里，从后往前合成。
4. 反向 kernel：同样的 tile 划分，从前往后遍历。`dL/da = S<gP,c> − (<gP, P − F> + gT·T)/(1−a)`，
   其中"后方颜色" P − F 用前向保存的总和减去前方累积得到，避免逐步除以 (1−a) 累积误差。

## 环境

RTX 5070 Laptop（sm_120，36 SM，8 GB），交流电源，torch 2.15.0+cu132，Triton 3.9.0，fp32。
计时用 kopt `bench()`：CUDA events，每次计时前清空 L2，报告中位数；对比项交替运行（A B A B），抵消温度漂移。

## 正确性

`tests/test_triton_raster.py`：14 个用例对比稠密参考版。

- 前向：最大误差 < 2e-5。覆盖 1/17/64/100/256px、N=0…500、极小图元、padding 图元、α 截断、硬边 β=8。
- 反向：xy、σ、θ、β、rgb、α 六组梯度的最大误差 ≤ 2e-3·max|grad| + 1e-4，并验证了分解器实际用的损失形式。
- 确定性：v1（原子加）两次运行的梯度不是逐位一致；v2 起**逐位确定**。
- 端到端：同一配置分解 24 张图，平均 PSNR 33.97 dB（torch）对 33.86 dB（Triton），差值在优化随机分歧的噪声内。

## 结果

### 对比稠密参考版

| 场景 | torch 稠密版 | Triton v1 | 加速比 |
|---|---|---|---|
| 分解器单步（前向+反向），B=4，N=256 | 84.29 ms | 1.314 ms | 64× |
| 整图渲染（前向），B=4，N=960 | 107.55 ms | 0.616 ms | 175× |
| 分解器单步，B=16 | 显存溢出 | 3.98 ms | — |

### 迭代过程（分解器单步，B=16，N=256，256px）

| 版本 | 改动 | 中位数 | 依据 |
|---|---|---|---|
| v1 | tile 光栅化，反向用原子加 | 3.86 ms | 剖析：反向 kernel 占 79%（3.14 ms） |
| ✗ | warp 数从 4 改到 1/2/8 | 3.99–5.33 ms | 跨 warp 的 barrier 不是瓶颈，**回退** |
| 实验 | 原子加换成普通写入（结果错误，仅计时） | 2.88 ms | 原子加的地址冲突约占 1.2 ms |
| v2 | 每个 (图, tile, 图元) 写自己的部分和，再沿 tile 维求和 | 3.03 ms | 1.27×，而且梯度变成确定性的 |
| v3 | 按椭圆自身朝向做分离轴测试，剔除空 tile | **2.44 ms** | (图元, tile) 组合减少到 70.5%，1.22× |

v3 的剖析：每步 GPU 时间 2.25 ms，其中反向 kernel 1.19 ms，前向 0.20 ms，其余约 0.85 ms 分散在约 195 个 torch 小 kernel（分箱、打包、求和、loss）。

### 分解器端到端（256px，合成场景）

| 后端 | batch | 每张图 | 显存峰值 |
|---|---|---|---|
| torch 稠密参考版 | 8 | 19.8 s | 3.86 GiB |
| Triton v3 | 8 | 1.4 s | 0.10 GiB |
| Triton v3 | 16 | **0.8 s** | 0.19 GiB |

3 万张图：约 165 GPU 小时 → 约 7 GPU 小时（5070 Laptop），租卡后可以继续加大 batch。

## 剩余空间

- 约 0.85 ms 花在 torch 小 kernel 和启动开销上：可以把分箱写成一个 kernel，或用 CUDA Graph 录制整步。
- 反向每处理一个图元要做 10 次块内归约：可以合并成一次多列归约，或只在 warp 内归约。
- 尚未用 ncu 查看 SM 吞吐和 stall 原因。这台机器需要 root 权限：
  `sudo ncu --set full -k regex:_bwd_kernel -c 1 -o bwd "$HOME/AI infra/.venv/bin/python" bench/bench_raster.py`
- 整图渲染的前向在 v3 下持平：多出来的剔除计算和 kernel 节省的时间相互抵消。可以在纯前向场景关掉 OBB，或把剔除挪进 kernel。

复现：`PYTHONPATH=~/.claude/skills/kernel-opt python bench/bench_raster.py`
